# Assignment 01: "Why are we here?"

## Why Are We Here?

### 1. Introduction: The Question in 2026

In 2026, AI can generate working code from a natural-language prompt ([GitHub Docs](https://docs.github.com/en/copilot/concepts/completions/code-suggestions)). As an art and design student who is new to programming, this makes me question why I should learn it. If AI can write code faster than I can, my goal should not be to compete with it. I am learning programming so I can understand what AI is doing, give it precise instructions, and decide whether its results are useful for my work. AI can speed up a technical process, but it cannot decide what I want an artwork to communicate. I still need to judge the result and choose what should change.

### 2. What Learning Programming Means Now

Learning programming does not mean writing every line from memory. It means understanding enough to follow what a program is doing. I need to recognise variables, parameters, loops, and randomness, and understand how changing them can change an image. This lets me describe a visual change more precisely, ask AI for a useful modification, and evaluate whether the result matches my intention. Without this understanding, I would depend on suggestions I could not properly question. I am not trying to become a better code writer than AI. I am trying to become an informed artist who can use AI while keeping responsibility for the direction and creative decisions in my work.

### 3. Example: Starting the Generative Artwork

The tutor provided the starting Python code as a class exercise based on Georg Nees' *Schotter* (1968–1970) ([Kunsthalle Bremen](https://onlinekatalog.kunsthalle-bremen.de/DE-MUS-027614/object/11801)). I did not create the original square-grid artwork or its starting code from scratch. Instead, I used AI to help me understand the existing Python code and make modifications to it. My own decisions came from changing the code and evaluating the visual results, including the later changes to `CHAOS`, square size, and outline colour. This taught me that learning programming also means understanding and modifying existing code, not only writing a program from the beginning. I still needed to recognise what the code was changing and judge whether the result matched my intention.

### 4. Example: Directing and Evaluating AI Output

The first `CHAOS` value was `1.0`, but when I looked at the image, the transition from order to disorder did not feel visually strong enough. I decided to increase the value to `2.0`, and used AI to help make this change in the code. The falling-apart effect became much clearer. Understanding what the parameter controlled helped me give AI a more precise instruction instead of asking for a vague improvement. It also helped me judge whether the change actually worked. I could compare the new image with what I wanted the artwork to communicate and make a decision based on the visual result. The AI helped carry out the change, but I was responsible for noticing the problem and deciding that a stronger value was needed.

### 5. Example: Making Creative Decisions Beyond the Prompt

After increasing `CHAOS`, I wanted the lower part of the artwork to feel less stable and more like it was disappearing. I decided to make the squares gradually smaller toward the bottom, then change the outlines from black to light grey. These changes made the lower squares feel as if they were fading away, rather than only becoming more disordered. AI helped me implement both changes in the code, but the visual decisions came from looking at the result and deciding what to change. Learning some programming helped me communicate these changes precisely and understand their implementation. As an art and design student who is new to programming, I remained responsible for the artistic judgement and for deciding what the final image should feel like.

### 6. Why This Matters for Artists and Designers

Learning some programming helps me move from simply accepting AI-generated results to actively shaping and evaluating them. I do not need to compete with AI at writing code. I need to understand enough to know what I am asking for, recognise when a result is weak or different from my intention, and make a more precise change. I saw this while modifying the square artwork in the class exercise, when I judged the visual effect of the `CHAOS` value, then decided how the size and colour should change. The code was important, but so was knowing what I wanted the image to do.

### 7. Conclusion: Learning to Direct, Not Compete

So, why are we here? I am not here to become faster than AI at writing code. I am here to understand programming well enough to use AI without losing my own judgement and creative direction. In my class exercise, AI helped implement the code, but I evaluated the visual results and decided to increase `CHAOS`, make the squares smaller, and fade the outlines. AI was part of the making process, not something I had to defeat. Learning programming means gaining enough understanding to work with this tool thoughtfully, question its results, and keep making decisions as an artist and designer.
